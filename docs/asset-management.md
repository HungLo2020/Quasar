# Asset management core

Implements issue #9 as a new independently usable `quasar-assets` crate. It
does not require assets in Git, a build script, editor, renderer or application
runner.

## Audit and decisions

Existing Quasar modules already load domain-specific data:
`quasar-tilemap::io` validates map-relative files with an `AssetRoot`;
`quasar-audio` decodes bytes and paths; `quasar-storage` resolves Basalt
directories. None provides generic virtual paths, mounts, typed handles, cache
budgets or dependency graphs. `quasar-assets` supplies that layer and leaves
format-specific parsing in loaders. The tilemap's stricter map-relative
`AssetRoot` remains intact to preserve its existing behavior and limits.

Decisions:

- Validate paths at construction and at serde deserialization, not at every use.
- Keep mounts file-system-agnostic through a small `AssetSource` trait; ship
  `FileSource` and `MemorySource`.
- Use explicit typed loader registration. Guessing a decoder from an extension
  would hide conflicts and make failures less deterministic.
- Keep a strong `Arc<T>` in `Handle<T>`. Eviction can then free cache bookkeeping
  without invalidating a value a game still holds.
- Store dependency metadata per loaded path and expose deterministic
  dependency/load-order queries and cycle errors.
- Make cache budgets soft while handles/dependents are live. Eviction is
  least-recently-used among safe candidates, never a dangling resource.
- Keep the core dependency-free. `serde`, `quasar-storage`, `diagnostics`,
  `async` and `hot-reload` are opt-in features.

## Public API

| Type | Purpose |
|---|---|
| `AssetPath` | Validated portable relative path; joins and prefix stripping |
| `AssetSource` | Read-only mounted source contract |
| `FileSource` | Canonicalized root with symlink-escape and size checks |
| `MemorySource` | Embedded/generated bytes and deterministic fixtures |
| `Asset` | Dependencies, schema version and approximate memory size |
| `AssetLoader` / `LoadContext` | Typed synchronous loading and schema helpers |
| `Bytes` / `BytesLoader` | Baseline raw-byte asset and loader |
| `AssetServer` | Mounts, loader registry, cache, budgets and graph queries |
| `Handle<T>` | Cheap typed strong handle with path/id/schema metadata |
| `CacheBudget` / `CacheStats` | Entry/byte limits and current usage |
| `AssetError` / `AssetErrorKind` | Explicit path, mount, I/O, schema, loader, budget, dependency and busy errors |

Lifecycle: register loaders, mount sources, call `load::<Loader>(path)`, use the
returned handle, and optionally set a budget. `dependencies`, `dependents` and
`load_order` inspect recorded graphs. `unload` refuses live handles/dependents;
`clear_cache` is always safe because live handles own their values.

Cargo and Basalt are both ordinary directories. `mount_file` works from a Cargo
checkout; with `storage`, `mount_basalt`/`FileSource::from_basalt` resolve the
packaged `app/<relative>` directory and fall back to the Basalt root.

## Async extension

Optional `async` and `hot-reload` features add a bounded worker and `notify`
watcher. `AsyncAssetServer::reload` invalidates dependent cache entries, loads a
new typed handle, and reports a server revision. Old handles remain valid because
they own their values. See [async assets](async-assets.md) for queue bounds,
cancellation, conflict handling, watcher events and the explicit GPU-adapter
boundary.

## Verification

```sh
cargo test -p quasar-assets
cargo test -p quasar-assets --features serde,storage
cargo test -p quasar-assets --features async,hot-reload,serde,storage,diagnostics
cargo clippy -p quasar-assets --all-targets -- -D warnings
cargo clippy -p quasar-assets --all-targets --features async,hot-reload,serde,storage,diagnostics -- -D warnings
```

Headless tests cover path rejection (absolute, empty, dot, traversal, backslash,
colon, control/NUL), longest-prefix mounts, duplicate mounts, symlink escape
rejection, file/memory reads, typed cache hits, entry-budget eviction, live
handles after cache clear, busy/dependency unload failures, dependency ordering
and cycles, schema mismatch, missing mounts/content/loaders, serde path
validation and Basalt mounts.

## Limitations

- The default server is synchronous. The `async` feature adds a bounded worker,
  but loader/file reads inside it remain synchronous; there is no async streaming
  or memory map. `hot-reload` reports filesystem paths but requires explicit typed
  reload requests. No compression container or automatic dependency prefetch.
- The cache budget uses source bytes or `Asset::memory_size`; it is an
  approximation, not an allocator measurement.
- `FileSource` has a default 256 MiB per-file limit and requires canonical paths
  that remain under its root; unusual filesystems that cannot canonicalize are
  unsupported.
- Dependencies are metadata from `Asset::dependencies`; the server verifies
  ordering and safety, not semantic correctness of a loader's list.
- No asset hashing, content addressing, remote sources or editor integration.
