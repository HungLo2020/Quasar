# Tilequest

A small scrolling top-down game exercising Quasar's runtime tilemap path. Find
three amber beacons, then reach the old gate in the southeast. Water, rocks,
ruins and trunks block movement. A 2,048×1,536 world contains 49,152 stored cells;
only tiles intersecting the camera become GPU quads. Foreground canopies,
parallax clouds, water/player animation, flipped sprites, and a screen-space HUD
share the same atlas and ordered 2D renderer.

```sh
cargo run -p tilequest
```

WASD/arrows move, P/Escape pauses, R restarts, Q quits. F11 toggles fullscreen;
F2 switches nearest/linear filtering; F3 switches integer/fit scaling. Losing
focus releases input and pauses the game. HUD hints describe the default preset.
Controls can be exported with `--write-default-bindings FILE` and loaded with
`--bindings FILE`. Simulation runs at a fixed 60 Hz, using integer positions and
axis-separated collision; this simple controller belongs to the game.

```sh
cargo run -p tilequest --no-default-features -- --headless --autoplay --ticks 6000 --record /tmp/quest.json --state /tmp/quest-state.json --screenshot /tmp/quest.png
cargo run -p tilequest --no-default-features -- --headless --replay /tmp/quest.json --state /tmp/replayed.json --screenshot /tmp/replayed.png
cargo run -p tilequest -- --autoplay --smoke-frames 40 --exercise-window --screenshot /tmp/native-quest.png
python tools/verify_tilemap.py
```

Headless mode needs no Vulkan/window dependencies. Its deterministic CPU reference
renderer uses the same Canvas as native GPU rendering. Replay files carry a version
and normalized-map fingerprint; mismatched maps/versions/inputs fail. Autoplay is
a game-specific pathfinding test client and completes the quest in 6,000 ticks.
Outputs are explicit paths, with atomic JSON writes through quasar-storage. The
example does not automatically save progress or overwrite controls.

Assets are original procedural pixel art generated by `assets/generate.py` using
Python's standard library. Running it regenerates the checked-in PNG, Tiled map,
and external TSJ. No downloaded art or external asset licenses are involved.
`quasar-tilemap` expands that TSJ, decodes the PNG, and supplies metadata/queries;
`quasar-render-2d` consumes VulkanicGAL for native rendering; `quasar-frame` handles
surface completion and resize recovery. No editor, ECS or game runner is required.

## Portable layout

Build `cargo build --release -p tilequest`, then distribute:

```text
Tilequest/
  app/bin/tilequest[.exe]
  app/assets/island.tmj
  app/assets/atlas.png
  app/assets/tilesets/island.tsj
```

Assets resolve from Basalt's executable-relative `app/assets`, independently of
the launch directory. Development runs fall back to this example's assets. Use
`--map FILE` to select another compatible map. The verifier copies the executable
and assets to a temporary package, launches it elsewhere, and compares pixels and
state. Native builds still require a compatible Vulkan runtime as described in
the root README; only Linux desktop graphics have been verified locally.

## Verification and performance

```sh
cargo test -p tilequest --no-default-features
cargo test -p tilequest --lib -- --include-ignored --test-threads=1
cargo run --release -p tilequest -- --autoplay --benchmark /tmp/tilequest-benchmark.json
python tools/benchmark_tilemap.py --output /tmp/tilemap-benchmark.json
```

The native benchmark runs 364 presented frames, excludes 64 warmup frames, and
reports CPU/GPU median time, tile traversal, draw batches, upload bytes, resource
churn and waits. It excludes screenshots and resize exercises; benchmark mode advances one simulation tick per frame so autoplay scrolls
independently of machine speed; normal gameplay uses elapsed time at 60 Hz. GPU timestamps may be unavailable on some drivers.
The separate CPU benchmark compares different stored map sizes at a fixed visible
area. Neither is a broad hardware performance claim or an end-to-end input latency
measurement. GPU tests compare rendered pixels with the CPU reference at several
camera/animation states. Native smoke testing exercises resize, fullscreen and
zero-sized-surface recovery and checks final resource balance.
